Professional Self-Assessment

The Computer Science program taught me to view software as something that other people must trust, use, and maintain, not simply something that runs. Throughout the program, I strengthened my technical skills while developing a professional mindset centered on quality, security, and maintainability. I am building my career toward Android and mobile application development, and this ePortfolio is organized around one application: a Weight Tracking app that I originally created in CS 360, Mobile Architecture and Programming, and then significantly enhanced for my capstone project. That second implementation is the clearest example of my growth as a computer science professional. When I reviewed my original application, I identified several weaknesses that I had not recognized when the software was first developed. Passwords were stored in plain text, floating-point values were compared incorrectly, database resources were not always released properly, and trend calculations relied on row position rather than actual dates. By the end of the program, I could identify these issues, explain their impact, implement appropriate solutions, and verify the improvements through automated testing. This process demonstrated how much my understanding of software engineering, databases, algorithms, and security had matured throughout the Computer Science program. Three values guide my work as a developer. First, software should be correct before it is clever. Second, technical decisions should be supported by evidence through testing and validation. Third, technical concepts should be communicated clearly so that both technical and non-technical audiences can understand them. These principles have shaped the way I approach software development and will continue to guide my professional growth.

Data Structures and Algorithms

The Computer Science program strengthened my ability to evaluate data structures and algorithms based on performance requirements and user needs. I learned that selecting the appropriate solution requires balancing efficiency, maintainability, and accuracy rather than simply implementing the first approach that works. For the Weight Tracking application, I replaced a simplistic trend calculation that relied on list position with a more sophisticated data-analysis pipeline. The enhanced solution incorporates a moving average, exponential smoothing using an alpha value of 0.3, regression-based trend analysis, and forecasting models based on actual calendar dates. These algorithms provide users with meaningful insights into their progress while minimizing the impact of short-term fluctuations in weight measurements. The final implementation also includes safeguards for edge cases. The application validates date parsing, prevents forecasts when trends are flat or moving away from a user's goal, and compares decimal values using tolerances instead of direct equality comparisons. In addition, I documented algorithm complexity, implementation trade-offs, and system limitations in a formal algorithm analysis report. Beyond the capstone project, courses focused on data structures and algorithms expanded my understanding of selecting appropriate data structures to achieve performance goals. Through implementing linked lists, stacks, queues, trees, and hash-based collections, I learned how different structures affect memory usage, insertion performance, searching efficiency, and scalability. These experiences reinforced that effective software engineering requires thoughtful decision-making about how data is stored, organized, and processed.

Software Engineering and Databases

My coursework provided extensive experience applying software engineering principles to build maintainable and scalable systems. Throughout the capstone enhancement process, I focused on improving the architecture of the Weight Tracking application to better align with modern Android development practices. The application was redesigned using the Model-View-ViewModel (MVVM) architectural pattern. User-interface components communicate with ViewModels, ViewModels communicate with repositories, and repositories handle interactions with the database layer. This separation of concerns significantly improved code organization, maintainability, and testability. To further improve software quality, I centralized authentication and session management responsibilities within a SessionManager rather than duplicating that logic throughout multiple screens. Shared constants and validation logic were also consolidated into reusable components, reducing redundancy and improving consistency across the application. Comprehensive JavaDoc documentation and GitHub version control practices further improved maintainability and supported professional development workflows. The database architecture underwent significant enhancement as part of the capstone project. I replaced the original SQLiteOpenHelper implementation with a Room-based architecture that follows modern Android development standards. The database includes five normalized tables representing users, weight entries, goals, BMI records, and annotations. Room entities, Data Access Objects (DAOs), repositories, and ViewModels work together to provide a scalable and maintainable solution. Additional database enhancements included foreign key relationships with cascade deletion, indexed queries, input validation, CSV import and export functionality, and data consistency enforcement. During testing, I discovered and corrected a defect that allowed one user's information to remain visible after another user signed in. By establishing proper user-to-data relationships throughout the schema, I eliminated this security and privacy concern. Testing played a critical role in validating these enhancements. The project includes more than 50 automated tests, including unit tests, DAO tests, user-interface tests, and a continuous integration pipeline using GitHub Actions. These tests validate forecasting logic, data processing, authentication functionality, password hashing, CSV import and export operations, validation rules, and database behavior. Developing such a comprehensive testing strategy reinforced the importance of proving software quality rather than assuming software quality.

Security

Security became one of the most valuable areas of growth throughout the Computer Science program. The capstone project provided an opportunity to evaluate my original implementation through a security-focused perspective and implement meaningful improvements. One of the most significant changes involved replacing plain-text password storage with a secure password-hashing solution. Passwords are protected using PBKDF2 with HMAC-SHA256, 120,000 iterations, a 256-bit derived key, and a unique random salt for every user. Authentication occurs through hash verification rather than SQL credential matching, and constant-time comparisons are used to minimize timing-based attacks. Beyond password protection, I implemented validation rules and data-layer safeguards that protect the application from invalid input and inconsistent data. Authentication responsibilities were centralized, database writes include error handling, and import operations validate data before it is stored. These enhancements significantly reduce the risk of exposing credentials or introducing invalid information into the system. I also applied the principle of least privilege throughout the application. File import and export functionality uses Android's file picker rather than requiring broad storage permissions. SMS permissions are requested only when reminder functionality is enabled, and users receive clear feedback when capabilities are unavailable on their device. Equally important, I learned to identify remaining security limitations. The application does not currently implement account lockout mechanisms, database encryption at rest, or encrypted session storage. Recognizing and documenting these limitations demonstrates a security mindset focused on continuous improvement rather than assuming a system is completely secure.
